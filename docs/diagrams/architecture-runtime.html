Architecture · go-starter

运行时拓扑：两个进程，同一套模块，靠 Postgres 交接

api 和 worker 是同一套代码的两个入口，都用 buildModules 构造全部五个模块，各自按配置连 Postgres 和 Redis。api 注册前台路由；配置了 HTTP_ADMIN_ADDR 时再起后台 server，页面经 go:embed 打进二进制。api 只入队、不消费任务，api 二进制还带 CLI 子命令（如 api staff create），执行完就退出，不起 server。worker 只注册任务和定时任务，:9090 只有健康检查和指标。下单时 order 在同一个事务里写订单并把 order_created 写进 river_job，worker 取到后由 fulfillment 在一个事务里扣库存、确认或收口订单，两个进程之间不直接通信。Redis 要么两个进程都配，要么都不配：worker 扣库存后要删商品缓存，只给 api 配时前台最多读到 5 分钟前的库存。没配 Redis 时，缓存退化为 Noop，限流退化为进程内存计数。
